## 精炼段

虚函数让"通过基类指针/引用调用的函数"在**运行时**按对象的真实类型分发到派生类版本——这就是多态，也是你 Cool 编译器里"动态分发"在 C++ 里的形态。语法三件套：基类用 `virtual` 声明、派生类用 `override` 显式覆盖、`final` 禁止再覆盖。**只有通过指针/引用**才触发动态绑定（值传递会切片，见 04）。两个必踩的点：**基类析构必须 virtual**（否则 `delete` 基类指针不调派生类析构），以及**纯虚函数** `= 0` 把类变成不能实例化的抽象类（≈接口）。底层实现是虚表 vtable——`06` 会拆开看，`17` 会对照你的 codegen。

---

## 0. 一句话直觉

> 你说 `shape.draw()`，但 `shape` 到底画圆还是画方，得看它**运行时**真实是谁。就像打电话给"客服"这一个号码，接起来可能是售前、售后、投诉——**同一个调用，接到不同的人**。这就是多态：**一套接口（`draw()`），多种实现（圆有圆的画法，方有方的画法），运行时按对象的真实类型自动选对版本。**

## 1. 没有虚函数的世界（静态绑定）vs 有虚函数的世界（动态绑定）

```cpp
class Shape {
public:
    void draw() { std::cout << "画一个形状\n"; }   // 非虚
};
class Circle : public Shape {
public:
    void draw() { std::cout << "画圆\n"; }         // 想"覆盖"，但没加 virtual
};

Circle c;
Shape& s = c;       // 基类引用指向派生类对象
s.draw();           // 输出"画一个形状"！—— 静态绑定：按 s 的静态类型 Shape 决定
c.draw();           // 输出"画圆" —— 直接调 Circle::draw
```

**问题**：`s` 明明引用着一个 `Circle`，却调了 `Shape::draw`。因为非虚函数是**静态绑定**——编译期按"变量声明的类型"决定调谁。

**加 `virtual` 之后**：
```cpp
class Shape {
public:
    virtual void draw() { std::cout << "画一个形状\n"; }   // 虚！
};
class Circle : public Shape {
public:
    void draw() override { std::cout << "画圆\n"; }         // override 覆盖
};

Circle c;
Shape& s = c;
s.draw();           // 输出"画圆"！—— 动态绑定：运行时按 s 的真实类型 Circle 决定
```

## 2. 语法三件套：virtual / override / final

| 关键字 | 位置 | 作用 |
|---|---|---|
| `virtual` | 基类声明 | 标记"这个函数可以被派生类覆盖，调用时动态分发" |
| `override` | 派生类 | 显式声明"我在覆盖基类虚函数"；**写错签名/基类没这个虚函数 → 编译报错**（强烈建议总是加） |
| `final` | 派生类（或类） | 禁止再被覆盖（`void draw() final;`）或禁止被继承（`class X final`） |

```cpp
class Shape {
public:
    virtual void draw() const;          // 虚函数
    virtual ~Shape() = default;         // 虚析构（见 §4）
};
class Circle : public Shape {
public:
    void draw() const override;         // 覆盖，且编译器帮你核对签名
};
class FilledCircle final : public Circle {
public:
    void draw() const final;            // 到此为止，子孙不能再覆盖
};
```

> **`override` 的价值**：不写它，若你把 `draw` 拼错成 `Draw`，编译器会**静默**当你在声明一个新函数（不覆盖任何东西），多态悄悄失效，bug 极难查。写了 `override`，编译器立刻报错。

## 3. 动态绑定的触发条件（务必记牢）

动态绑定**只发生在**：**通过基类的指针或引用**调用**虚函数**。三个条件缺一不可：

| 情形 | 是否动态绑定 |
|---|---|
| `Shape& s = c; s.draw();` | ✅ 引用 + 虚函数 |
| `Shape* p = &c; p->draw();` | ✅ 指针 + 虚函数 |
| `Shape s = c; s.draw();` | ❌ 值拷贝 → 切片（04），只剩 Shape |
| `c.draw();` | ❌ 直接用派生类对象，编译器已确定 |
| 构造函数/析构函数里调虚函数 | ❌ 不动态分发（见 §6 易错点） |

## 4. 虚析构函数（继承 + 多态最常见的生产事故）

```cpp
class Base {
public:
    ~Base() { std::cout << "Base 析构\n"; }   // 非虚析构（危险）
};
class Derived : public Base {
public:
    ~Derived() { std::cout << "Derived 析构（释放资源）\n"; }
};

Base* p = new Derived;
delete p;          // 只输出"Base 析构"！Derived 的析构没执行 → 资源泄漏 / 未定义行为
```

**原因**：`delete p` 按 `p` 的**静态类型** `Base` 决定调哪个析构；若 `~Base()` 非虚，就只调 `Base` 的析构，`Derived` 的成员（可能持有资源）永远不释放。

**铁律**：**只要一个类会被当作基类（尤其有虚函数），它的析构函数就必须是 `virtual`。** 反过来，若类不打算被继承，别乱加 virtual（会增加一个 vptr，见 `06`）。

```cpp
class Base {
public:
    virtual ~Base() = default;   // 虚析构，delete 派生类对象时安全
};
```

## 5. 纯虚函数与抽象类（≈接口）

```cpp
class Shape {                       // 抽象类：不能实例化
public:
    virtual void draw() const = 0;  // 纯虚函数：只声明、不实现，强制子类实现
    virtual ~Shape() = default;
};
class Circle : public Shape {
public:
    void draw() const override { std::cout << "画圆\n"; }
};

// Shape s;      // 错误：抽象类不能实例化
Shape* s = new Circle;   // OK：用指针/引用指向具体子类
```

- **纯虚函数** `= 0`：声明"我没有默认实现，派生类必须自己实现"。
- **抽象类**：含有至少一个纯虚函数的类，**不能实例化**，只能被继承。
- **接口**：全是纯虚函数（+ 虚析构）的抽象类，描述"能力"而非"数据"——这正是设计模式（依赖倒置）的基石。

> 对照你的 Cool 编译器：Cool 里很多类是"只声明方法签名、没有体"的抽象类，C++ 用 `= 0` 表达同一件事（`17` 详谈）。

   │                                      │
   │                                      ▼
   │                           vtable[draw 的槽位] = &Circle::draw

## 7. 易错点

1. **基类析构忘了 virtual**：`delete` 基类指针漏掉派生类析构 → 资源泄漏。**有虚函数的类析构必 virtual。**
2. **忘了写 `override`**：拼错签名变成"新函数"而非"覆盖"，多态静默失效。
3. **值传递切片导致多态失效**：参数写 `Shape` 而非 `const Shape&`。
4. **构造函数/析构函数里调虚函数**：此时对象的派生类部分还没构造完（或已析构完），虚函数**不会**分发到派生类版本，而是调当前类版本——容易踩空。
5. **滥用虚函数**：虚函数有开销（一次间接跳转 + 阻止内联，见 `06`），热点路径里能用模板/静态分发就别用虚函数（`14` 的性能工程会展开）。
6. **`final` 类 + 虚函数**：`final` 类的虚函数其实可以被编译器去虚化（devirtualization），但别依赖这个做性能优化。

1. **概念题**：动态绑定发生的三个必要条件是什么？为什么"通过值传递的基类对象"不能触发动态绑定？
2. **应用题**：设计一个 `Animal` 抽象类（纯虚 `speak()` + 虚析构），派生出 `Dog`、`Cat`；写一个 `void make_sound(const Animal&)` 函数，用多态让 `Dog` 和 `Cat` 各叫各的。确保析构正确。
