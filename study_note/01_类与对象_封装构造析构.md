## 精炼段

`class` 的本质是「把数据 + 操作数据的方法打包成一个整体」，用 `private` 隐藏内部、只暴露 `public` 接口来保护不变量（invariant）。构造函数管对象的"出生"（分配/初始化），析构函数管"死亡"（释放资源），这一对就是 RAII 的雏形——正是你 CUDA 里 `cudaMalloc/cudaFree` 必须成对出现、你却总忘 `free` 的那个痛点的自动化解。`struct` 与 `class` 的唯一区别是默认访问权限（`struct` 默认 public、`class` 默认 private）。成员函数内部有隐式的 `this` 指针指向当前对象，这和你 Cool 编译器里"方法把 `self` 作为隐藏参数传入"是同一件事。

---

## 0. 一句话直觉

> 竞赛里你写：
> ```cpp
> struct Node { int v; int next; };          // 数据
> void add_edge(Node* adj, ...) { ... }      // 操作数据的裸函数（在别处）
> ```
> 数据 `Node` 和操作 `add_edge` 是**分离**的。`class` 做的事就是：**把 `add_edge` 搬进 `Node` 里面，变成它的"成员函数"**，再给数据加一道"只准通过公开接口访问"的门。于是数据和操作它的人住在同一个盒子里，谁也别想绕过规则乱改数据。

## 1. 为什么需要 class：从你熟的 struct 出发

**问题场景**：你写一个动态矩阵（HPC 里天天见），需要记住「行数、列数、数据指针」三个量，并且保证"数据指针指向的内存恰好是 rows×cols 个 float"。

竞赛写法（过程式）：
```cpp
struct Mat { int r, c; float* d; };
Mat make(int r, int c) { return {r, c, new float[r*c]()}; }   // 手动分配
void free_mat(Mat& m) { delete[] m.d; }                        // 手动释放
// 坑：谁忘了调 free_mat，就内存泄漏；谁改了 m.r 忘了同步，数据就错乱
```
问题：`r`、`c`、`d` 之间有一个**必须恒成立的关系**（`d` 指向 `r*c` 个 float），但这个关系**没有任何东西保护**——任何代码都能 `m.r = 999` 把它破坏，也能忘记 `free_mat`。

`class` 的解法：把「数据」和「维护这个关系的方法」关进同一个盒子，数据私有、操作公开：
```cpp
class Matrix {
public:
    Matrix(int r, int c) : rows_(r), cols_(c), data_(new float[r*c]()) {}  // 出生时保证关系成立
    ~Matrix() { delete[] data_; }                                           // 死亡时自动释放
    float& at(int i, int j) { return data_[i*cols_ + j]; }                  // 唯一访问入口
private:
    int rows_, cols_;   // 外部不能直接改，关系不会被破坏
    float* data_;
};
```
**关键收益**：① `rows_/cols_/data_` 只能在 `Matrix` 内部改，不变量有了"守护者"；② 释放内存这件事从"记得调 `free_mat`"变成"编译器自动调析构"——你永远不可能忘记。

## 2. struct vs class：本质区别只有默认访问权限

| | `struct` | `class` |
|---|---|---|
| 默认成员访问权限 | **public** | **private** |
| 默认继承方式（`04` 细讲） | public | private |
| 其它能力 | 完全相同（都能有构造函数、成员函数、析构、继承……） | 完全相同 |

**一句话结论**：`struct` 和 `class` 是**同一个东西的两套默认值**，不是两种类型。约定俗成：**纯数据聚合用 `struct`，有行为/要保护不变量用 `class`**（C++ Core Guidelines C.2）。

```cpp
struct S { int x; };      // x 默认 public，外部可 s.x 直接访问
class C { int x; };       // x 默认 private，外部 c.x 报错
```

## 3. 访问控制：封装的三道门

| 访问级别 | 谁能访问 | 用途 |
|---|---|---|
| `public` | 任何人 | 类的**接口**（对外承诺的能力） |
| `private` | 只有本类的成员函数 / `friend` | 类的**实现细节 + 不变量**（内部自由改） |
| `protected` | 本类 + 派生类（`04` 细讲） | 给子类的"受保护接口" |

**设计原则（核心！）**：**数据成员一律 `private`，通过公开方法暴露最小必要接口**。这叫"封装"——不是把东西藏起来故弄玄虚，而是**把「状态如何变化」的控制权收归类自己**，让非法状态"根本写不进去"，而不是"写进去了靠你检查"。

```cpp
class BankAccount {
public:
    void deposit(double amt) {          // 唯一能改余额的入口
        if (amt > 0) balance_ += amt;   // 在这里保证不变量：余额不会因非法操作变成负的
    }
    double balance() const { return balance_; }
private:
    double balance_ = 0.0;   // 只有 deposit 能改
};
// 外部无法 account.balance_ = -100; —— 非法状态从根上被禁止
```

## 4. 构造函数：对象的"出生手续"

构造函数名与类名相同、无返回类型，在对象创建时**自动调用**，负责把对象初始化到合法状态。

### 4.1 成员初始化列表（Member Initializer List）——本篇第一个要死记的点

```cpp
Matrix(int r, int c) : rows_(r), cols_(c), data_(new float[r*c]()) {}
//                     └────────── 这就是初始化列表，冒号后、花括号前 ──────────┘
```

**为什么必须用它，而不是在函数体里赋值？** 三条理由，前两条是硬约束：

1. **某些成员只能初始化、不能赋值**：`const` 成员、引用成员、没有默认构造函数的类类型成员——它们必须出现在初始化列表里，否则编译报错。
2. **顺序**：成员按**声明顺序**初始化（不是列表书写顺序！），若顺序不一致会有坑（见"易错点"）。
3. **效率**：初始化列表是"一步到位构造"，函数体赋值是"先默认构造、再赋值"（对 `string`/`vector` 这类成员会白做一次默认构造）。对你的 `float*` 无所谓，对复杂成员是实打实的开销。

```cpp
class Person {
public:
    Person(const std::string& name) : name_(name) {}   // 一步构造 name_
    // 若写成 { name_ = name; } 则是：先默认构造空 string，再赋值 —— 多一次无谓操作
private:
    std::string name_;
};
```

### 4.2 几种常见构造函数

```cpp
class Vec {
public:
    Vec() : x_(0), y_(0) {}                    // ① 默认构造（无参）
    Vec(int x, int y) : x_(x), y_(y) {}        // ② 带参构造
    Vec(int v) : Vec(v, v) {}                  // ③ 委托构造（调用另一个构造函数）
    Vec(const Vec& o) = default;               // ④ 拷贝构造（02 细讲）
    Vec(Vec&& o) = default;                    // ⑤ 移动构造（08 细讲）
private:
    int x_ = 0;                                // ⑥ 类内默认初始化（C++11）
    int y_ = 0;
};
```

- **`= default`**：让编译器替我生成那个构造函数的默认实现。
- **`= delete`**：显式禁止（如 `Vec(const Vec&) = delete;` 禁止拷贝，很多 RAII 资源类如此）。
- **类内默认初始化**（`int x_ = 0;`）：若构造函数初始化列表没提到该成员，就用这个默认值——比"每个构造函数都写一遍"省事且不易漏。

### 4.3 什么情况下编译器会"偷偷"替你生成构造函数

如果一个类**没有任何用户声明的构造函数**，编译器会生成一个隐式默认构造函数；一旦你声明了任意一个构造函数，编译器**不再生成**默认构造函数。所以：

```cpp
struct A { int x; };          // 隐式默认构造：A a;  OK（x 未初始化，垃圾值！）
struct B { B(int){} };        // 有带参构造 → 不再有默认构造
// B b;                        // 编译错误：没有默认构造函数
```

> 这也是 `struct S { int x; }; S s; s.x = 1;` 里 `s.x` 之前是垃圾值的根源——隐式默认构造**不会**帮你清零内置类型成员。这也是为什么本篇 demo 里用 `new float[r*c]()`（带 `()`）来零初始化。

## 5. this 指针：谁在调用我

在**每个非静态成员函数**内部，都有一个隐式的指针 `this`，指向"当前正在被操作的那个对象"。

```cpp
class Counter {
public:
    void add(int v) {
        count_ += v;            // 等价于 this->count_ += v;
        // this 的类型是 Counter*（const 成员函数里是 const Counter*）
    }
private:
    int count_ = 0;
};
Counter a, b;
a.add(1);   // 调 add 时，this 指向 a；等价于底层 add(&a, 1)
b.add(1);   // this 指向 b
```

**为什么这和你学编译器有关（重点！）**：成员函数和普通函数的**唯一底层区别**，就是多了一个隐藏的第一个参数 `this`。你 Cool 编译器 codegen 里，方法体里用到的 `self` 变量、以及 `self.method()` 的调用，翻译到 LLVM IR 时就是把对象指针作为第一个参数传进去。C++ 的成员函数调用 `a.add(1)`，编译后就是 `Counter::add(&a, 1)`——**同一件事**。`17` 会带你对照。

**什么时候必须显式写 `this`**：① 成员名与参数名冲突时（如构造函数的 `rows_(r)` 已靠名字规避）；② 返回自身引用做链式调用：`return *this;`。

## 6. 析构函数：对象的"临终遗嘱"（RAII 预告）

析构函数名是 `~类名`，无参无返回，在对象**离开作用域**或**被 delete** 时自动调用，负责释放资源。

```cpp
~Matrix() { delete[] data_; }   // 与构造函数里的 new[] 严格配对
```

**这就是 RAII 的雏形**（Resource Acquisition Is Initialization，资源获取即初始化，`07` 详讲）：

> **资源在构造函数里获取，在析构函数里释放；对象的生命周期 == 资源的生命周期。** 对象活着资源就在，对象死了资源自动归还，**中间任何 `return`、任何异常，析构函数都会被编译器自动调用**——你永远不需要"记得"释放。

对照你的 CUDA 经验：
```cpp
// 竞赛式（危险）：任何提前 return 都漏 cudaFree
float* buf; cudaMalloc(&buf, n);
if (bad) return;          // 漏了 cudaFree → 显存泄漏
cudaFree(buf);

// RAII 式（安全）：析构自动 cudaFree，哪怕抛异常/提前 return 也安全（07/09 展开）
struct CudaBuf { float* p; CudaBuf(size_t n){ cudaMalloc(&p,n); } ~CudaBuf(){ cudaFree(p); } };
```

**构造函数/析构函数有明确的一生**：
```
创建对象 → [构造函数执行] → 使用对象 → [析构函数执行] → 内存回收
```

## 7. 对象内存布局（预览，`06` 细讲）

非多态类（没有虚函数）的对象，成员按**声明顺序**在内存里**连续排布**（中间可能有对齐填充）：

```
Matrix 对象 (rows_=2, cols_=3)
内存地址低 → 高
┌────────────┬────────────┬────────────┐
│ rows_ (int) │ cols_ (int) │ data_ (指针) │   ← 按声明顺序
│  offset 0  │  offset 4  │  offset 8  │
└────────────┴────────────┴────────────┘
sizeof(Matrix) == 16 字节（x64：int 4 + int 4 + 指针 8）
```
注意：`data_` 是**指针**，它指向的另一块堆内存（rows×cols 个 float）在对象外部——对象只存"指针"本身，不存数据本身。理解这一点，是理解"拷贝 vs 浅拷贝 vs 深拷贝"（`02`）和"值语义 vs 引用语义"的前提。

## 8. 权衡与取舍

| 选择 | 代价 | 何时用 |
|---|---|---|
| 数据 `private` + 公开接口 | 多写几行 getter/setter | 几乎总是（保护不变量） |
| 数据 `public`（裸 struct） | 任何人都能破坏不变量 | 纯数据聚合、无约束（如 `struct Point{int x,y;}`） |
| 成员初始化列表 | 顺序易错（见下） | 总是用，别用函数体赋值 |
| 资源在构造获取/析构释放 | 需理解生命周期 | 任何持有资源的类（首选，见 `07`） |

## 9. 易错点（竞赛 C++ 最容易踩的坑）

1. **初始化列表顺序 ≠ 书写顺序**：成员按**声明顺序**初始化。若初始化列表写成 `: cols_(c), rows_(r)` 而声明是 `rows_; cols_;`，则先初始化 `rows_`（用的是 `c` 的值！）再 `cols_`——静默错误。**解决：初始化列表顺序永远与声明顺序一致，并开 `-Wall`。**
2. **`struct` 里 `int x;` 默认是垃圾值**：隐式默认构造不清零内置类型。要么类内默认初始化 `int x = 0;`，要么 `new T[n]()` 加 `()`。
3. **析构函数忘了配对 `new`**：`new[]` 必须配 `delete[]`（不是 `delete`）；`new` 配 `delete`。混用是未定义行为。
4. **裸指针成员 + 默认拷贝 = 二次释放**：`Matrix b = a;` 会**浅拷贝指针**，`b` 和 `a` 的 `data_` 指向同一块内存，两个析构都 `delete[]` 它 → 崩溃。这正是 `02` 要讲的"三法则"。**在本篇 demo 里，你能亲手制造并观察这个崩溃。**
5. **构造函数不该调用虚函数**（`05`/`06` 细讲）：构造时对象还没"长成"派生类，虚函数不会按你想象分发。
