## 精炼段

C++ 是值语义语言，"复制"到处都是；但对持有大资源（buffer、矩阵、`unique_ptr`）的对象，深拷贝是灾难。移动语义解决它：**右值引用 `T&&` 标记"这个对象是临时的、即将销毁，你可以直接抢走它的资源"**。`std::move(x)` 本身不移动任何东西，它只是把 `x` 转成右值引用（一个 cast），真正的"移动"发生在移动构造/移动赋值里——把资源指针从源对象**搬**到目标，把源掏空。`std::forward` 用于**完美转发**：在模板里把参数的"左值性/右值性"原样传给下一个函数。配合返回值优化（RVO），现代 C++ 让"传大对象"从"复制一整块"变成"改一个指针"。

---

## 0. 一句话直觉

> 你要搬家，两个选择：① 复印所有家具到新家（复制，贵）；② 把家具**搬**过去，旧家只剩空房（移动，便宜）。移动语义就是让编译器在"对方是临时对象、马上要扔"的时候，自动选择"搬"而不是"复印"。对 HPC 里的超大 buffer 来说，这一下省掉整块内存的拷贝，只剩"改一个指针 + 置空源指针"。

---

## 1. 先分清左值 / 右值

| | 左值 lvalue | 右值 rvalue |
|---|---|---|
| 直觉 | 有名字、有身份、能取地址、活很久 | 临时的、即将销毁、没有稳定身份 |
| 例子 | `x`、`arr[0]`、`*p`、`str` | `42`、`x + y`、`std::move(x)`、函数返回的临时对象 |
| 能否取地址 | `&x` 合法 | `&(x+y)` 非法 |

**一句话记忆**：**"有名字的、能再被用到的"是左值；"用完就扔的一次性值"是右值。**

---

## 2. 右值引用 `T&&`：标记"可以抢"

```cpp
void f(int& x)  { std::cout << "左值引用\n"; }   // 绑定左值
void f(int&& x) { std::cout << "右值引用\n"; }   // 绑定右值

int a = 1;
f(a);          // 左值引用
f(1);          // 右值引用（1 是临时值）
f(std::move(a)); // 右值引用（把 a 强行当右值）
```

右值引用的核心用途是**区分"可以安全抢资源"的场景**，从而在重载里选到移动版本：

```cpp
std::vector<int> build() { return std::vector<int>{1,2,3}; }  // 返回临时对象
std::vector<int> v = build();   // build() 返回的是右值 → 走移动构造，不复制
std::vector<int> w = v;         // v 是左值 → 走拷贝构造（v 还要用，不能抢）
```

## 3. std::move：不是"移动"，是"转换"

**最容易被名字误导的点**：`std::move` **不做任何移动**，它只是 `static_cast<T&&>(x)`——把一个左值转成右值引用，从而"允许"后续的移动构造/赋值去抢资源。

```cpp
template<class T> constexpr T&& move(T&& t) noexcept {
    return static_cast<T&&>(t);
}
// 就这么点：一个 cast。真正的移动是下面的移动构造函数干的活。
```

真正的"移动"在移动构造函数/移动赋值里：
```cpp
class Matrix {
public:
    // 移动构造：把源对象的资源"搬"过来，源被掏空
    Matrix(Matrix&& o) noexcept
        : rows_(o.rows_), cols_(o.cols_), data_(o.data_) {   // 直接接管指针
        o.data_ = nullptr;      // 关键！把源置空，防止源析构时 delete 掉已被我接管的资源
        o.rows_ = o.cols_ = 0;
    }
    // 移动赋值同理：先释放自己的旧资源，再接管源的
    Matrix& operator=(Matrix&& o) noexcept { ... }
private:
    int rows_, cols_; float* data_;
};
```

**为什么移动构造通常标 `noexcept`**：`vector` 扩容时，若元素的移动构造是 `noexcept`，`vector` 才敢用移动（否则退化为拷贝以保证异常安全）——性能差距巨大（`09`/`14` 展开）。

## 4. 完美转发 std::forward 与万能引用

**问题**：写一个包装函数 `wrap`，想把参数"原封不动"转发给 `f`——左值还是左值、右值还是右值，不能丢失。

```cpp
template<class T>
void wrap(T&& arg) {              // T&& 在模板里是"万能引用/转发引用"
    f(std::forward<T>(arg));      // 完美转发：保留 arg 的左右值性
}
wrap(x);        // x 是左值 → forward 成左值 → f(左值引用版)
wrap(5);        // 5 是右值 → forward 成右值 → f(右值引用版)
```

- **万能引用 `T&&`**：只有当 `T` 是被**推导**出来的模板参数时，`T&&` 才是万能引用（能同时绑左值右值）；非模板的 `int&&` 就是普通右值引用。
- **`std::forward<T>(arg)`**：`T` 是左值类型就转成左值，`T` 是右值类型就转成右值——靠**引用折叠**规则实现（`T& &&`→`T&`，`T&& &&`→`T&&`）。
- **`std::move` vs `std::forward`**：`move` 无条件转右值；`forward` 有条件（按 T 推导）保持原样。**转发用 forward，主动移动用 move。**

> 完美转发是 `make_unique`/`make_shared`/`emplace_back` 这些"把参数原样传给构造函数"的设施的地基，也是模板库（`12`）的核心技巧。

## 5. 返回值优化 RVO / 拷贝省略（Copy Elision）

你以为"返回值"会复制，其实编译器经常**原地构造**、一次都不复制：

```cpp
Matrix make() {
    Matrix m(1000, 1000);
    return m;          // 命名返回值优化 NRVO：m 直接构造在调用者的接收处
}
Matrix a = make();     // 自 C++17 起，这种 prvalue 返回的拷贝省略是"强制"的
```
- **自 C++17**，从临时对象（prvalue）初始化对象的拷贝/移动是**保证省略**的（不再是优化，是语言规定）。
- 即便如此，**移动构造仍必须可访问**（编译器仍会做编译期检查），所以 02 里"三法则的类想移动要显式补移动"依然重要。

> 结论：现代 C++ 里"按值返回大对象"通常**零拷贝**（要么移动、要么 RVO 直接省略）。别再用"怕复制"当理由返回裸指针/引用，那才是危险来源。

## 6. 移动后，源对象是什么状态？

**移动后，源对象处于"有效但未指定"（valid but unspecified）状态**——你可以安全地析构它、给它赋新值，但**不该再依赖它的旧内容**。

```cpp
std::vector<int> a{1,2,3};
std::vector<int> b = std::move(a);
// a 现在是什么？标准说"有效但未指定"：通常为空，但不保证
a.clear();        // OK：给它赋新值/清空是合法的
// std::cout << a[0];  // 危险：别假设 a 还留着旧数据
```

> 你移动构造里把源 `data_` 置 `nullptr`，就是为了让源对象保持"有效"（析构 `delete[] nullptr` 是安全的）。

## 7. 与你的 infra/CUDA 工作的直接联系

- **buffer 所有权转移**：一个融合算子的输出 buffer，要交给下一个算子——用 `std::move` 转移所有权，而不是拷贝整块显存。`unique_ptr<Tensor>` 的移动就是"改指针"，零拷贝。
- **容器的零拷贝扩容**：`vector<Tensor>` 扩容时，若 `Tensor` 的移动构造是 `noexcept`，扩容就是"搬"而不是"逐元素拷贝"——大 buffer 下这是数量级的性能差异。
- **`emplace_back` vs `push_back`**：`push_back(Tensor(...))` 先构造临时再移动/拷贝；`emplace_back(args...)` 直接在容器里原地构造，省掉临时对象——都是移动语义思想的延伸。

---

## 8. 易错点

1. **`std::move` 之后继续用源对象**：移动后源状态未指定，别读它的旧内容。
2. **忘了移动构造标 `noexcept`**：`vector` 扩容时会退化成拷贝（异常安全考虑），性能暴跌。
3. **万能引用误用**：非模板上下文里写 `int&&` 不是万能引用；只有 `T&&` 且 `T` 被推导才是。
4. **`std::forward` 和 `std::move` 混用**：转发场景用 `forward`（保左右值性），主动移动用 `move`。
5. **返回局部变量的 `std::move` 是画蛇添足**：`return std::move(m);` 反而**抑制 NRVO**，让编译器真的去移动（多一次操作）。**直接 `return m;`** 让 RVO 工作。
6. **把 `const` 对象 move**：`const T&&` 只能绑定 const 右值，移动构造通常要非 const 才能"掏空"源——`const` 对象移动会退化到拷贝。
