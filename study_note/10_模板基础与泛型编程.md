## 精炼段

模板是"**类型参数化的代码**"：`template<class T> T max(T a, T b)` 里的 `T` 是占位符，编译器在**编译期**遇到 `max<int>`、`max<double>` 时，各自生成一份专用代码（这叫**实例化 instantiation**）。它分函数模板、类模板、非类型参数（`std::array<int, 5>` 的 `5`）三类。模板是**编译期多态**：零运行时开销（没有虚表的间接跳转），代价是**代码膨胀**（每种类型一份）和编译变慢。模板定义必须放在**头文件**（实例化点要能看到完整定义）。你竞赛里用的 `vector`、`sort` 全是模板——本篇讲清它们背后的"为什么"。

---

## 0. 一句话直觉

> 你写 `sort(v.begin(), v.end())`，`v` 可以是 `vector<int>` 也可以是 `vector<double>` 甚至 `vector<string>`——**同一份 sort 代码，适用所有类型**。这靠的不是 `void*` 或宏，而是模板：你写"对任意类型 T 排序"的**通用逻辑**，编译器在编译时看到你用 `int`，就自动生成一份"对 int 排序"的专用代码；看到 `string`，再生成一份"对 string 排序"。**模板 = 让编译器替你复制粘贴代码，并把类型安全地填进去。**

## 1. 函数模板

```cpp
template<class T>          // 或 template<typename T>，class/typename 在这里等价
T max2(T a, T b) {
    return a > b ? a : b;  // 对"任意可比较的 T"都成立
}

int    i = max2(3, 5);        // 实参推导：T = int
double d = max2(3.14, 2.7);   // T = double
// max2(3, 2.7);              // 错误：T 不能同时是 int 和 double（不自动隐式转换）
```

**模板实参推导**：编译器从实参类型反推 `T`。若有歧义，可显式指定：`max2<double>(3, 2.7)`（此时 `3` 会被转成 `double`）。

**为什么不用 `void*` 或宏？**
- `void*`：丢掉类型信息，要手动 cast，不安全、易错。
- 宏：文本替换，不检查类型、作用域混乱、难调试。
- 模板：**编译期强类型检查**，类型安全，且能内联优化。

## 2. 类模板

```cpp
template<class T>
class Vector {                 // 一个"任意元素类型"的动态数组（简化版）
public:
    void push_back(const T& v) { /* ... */ }
    T& at(std::size_t i)       { return data_[i]; }
private:
    T* data_;
    std::size_t size_;
};

Vector<int>    vi;             // 实例化出 int 版
Vector<std::string> vs;        // 实例化出 string 版
```

**类模板的成员函数也是模板**，且**只在被用到时才实例化**（惰性实例化）——所以类模板可以有"部分成员对某些 T 不成立"的情况，只要你不调用它们就不会报错。

**成员函数定义在类外**的写法：
```cpp
template<class T>
void Vector<T>::push_back(const T& v) { /* ... */ }
//   注意：要写 Vector<T>::，且 template<class T> 要重复声明
```

## 3. 非类型模板参数

模板参数不一定是类型，也可以是**编译期常量**：

```cpp
template<class T, std::size_t N>          // N 是"非类型参数"（编译期常量）
class Array {                              // 相当于 std::array
public:
    T& operator[](std::size_t i) { return data_[i]; }
private:
    T data_[N];                            // 数组大小在编译期确定，栈上分配
};

Array<int, 5> a;      // 栈上 int[5]，无堆分配、无指针间接
```
- 这就是 `std::array<int, 5>` 的原理：**大小进类型，编译期定死，零堆开销**——比 `vector` 快（无堆分配），但不能动态改大小。
- 非类型参数可以是整数、枚举、指针等（C++20 还放宽到浮点/类类型，`16`）。

## 4. 实例化与代码膨胀（模板的代价）

```cpp
max2(3, 5);        // 生成 max2<int>
max2(1.5, 2.5);    // 生成 max2<double>
max2('a', 'b');    // 生成 max2<char>
// 三种类型 → 三份机器码
```

- **代码膨胀（code bloat）**：每种类型组合都生成一份代码，二进制变大、编译变慢。
- **这是模板"零运行时开销"换来的代价**：编译期多态用"更多机器码"换"无间接跳转"。
- **缓解**：现代编译器会做模板合并（对指针等做薄封装）、`extern template` 显式实例化等。工程里一般不用过度担心，但要知道这个 trade-off。

---

## 5. 编译期多态（模板）vs 运行期多态（虚函数）

| | 模板（编译期多态） | 虚函数（运行期多态，05/06） |
|---|---|---|
| 何时决定 | **编译期** | **运行期** |
| 机制 | 为每类型生成专用代码 | vptr → vtable → fn |
| 开销 | 无间接跳转、可内联 | 两次间接寻址、难内联 |
| 代价 | 代码膨胀、编译慢 | 每对象 +8 字节、调用慢 |
| 何时用 | 类型**编译期已知**、追求性能（HPC 首选） | 类型**运行期才知道**、需要统一接口 |

> **这是你 HPC/infra 里最重要的一个权衡**：融合算子、矩阵库（Eigen、cuBLAS 风格）几乎全是模板——因为类型和维度编译期就确定，要榨干每一点性能。而"运行期才确定类型"的插件/动态加载场景才用虚函数。C++ 的两种多态，你要能一眼判断该用哪个（`14` 会再谈性能）。

## 6. 模板定义必须放在头文件

**规则**：模板的**完整定义**必须在"实例化点"可见。因为编译器看到 `max2<int>` 时，要现场生成代码，所以它必须能看到函数体。

```cpp
// max.h（模板定义放头文件，而不是 .cpp）
template<class T> T max2(T a, T b) { return a > b ? a : b; }

// 若把定义放 max.cpp 里，其它翻译单元 include 头文件后调用 max2<int>，
// 会链接报错 undefined reference —— 因为编译时看不到定义，没法实例化。
```
> 这和你 13 篇要学的"普通函数声明放头、定义放 cpp"的规则**相反**——是模板最常踩的坑。例外：`extern template` 显式实例化可以把实例化集中到一处（进阶）。

---

## 7. 易错点

1. **模板定义放 .cpp** → 链接错误 undefined reference。定义放头文件。
2. **`max2(3, 2.7)` 推导歧义** → T 无法同时是 int 和 double。显式 `max2<double>(3, 2.7)` 或统一类型。
3. **`template<class T>` 与 `template<typename T>` 混用**：二者等价，但团队内统一风格。
4. **类模板成员函数类外定义忘了 `template<class T>`** 和 `Vector<T>::` 前缀 → 编译错误。
5. **把模板当"万能胶"滥用**：模板让代码更抽象，但错误信息会变得极其难读（C++20 concepts 能缓解，`11`）。
6. **非类型参数传运行期变量**：`int n; Array<int, n> a;` 报错——`n` 必须编译期常量（`constexpr`）。

## 8. 自测题

1. **概念题**：模板实例化是什么？它如何带来"零运行时开销"与"代码膨胀"这两个相反的结果？
2. **应用题**：写一个函数模板 `sum(T a, T b)` 和一个类模板 `Pair<A, B>`（存两个不同类型的值），并在 `main` 里分别用 int、double、string 实例化验证。
3. **思考题**：为什么模板定义必须放头文件，而普通函数定义可以放 .cpp？从"编译器什么时候需要看到定义"这个角度解释两者的区别。
