## 精炼段

C++ 的值语义意味着对象会被"复制"来"复制"去（初始化、传参、返回、赋值），但**编译器默认的拷贝是"按位浅拷贝"——只复制指针本身，不复制指针指向的内存**。一旦类持有堆资源（指针、文件、锁、显存），浅拷贝会让两个对象共享同一份资源，析构时二次释放 → 崩溃。**三法则**：需要自定义析构/拷贝构造/拷贝赋值三者之一，几乎必然三者都要（因为你在管理一份资源）。C++11 加入**移动**（五法则：再补移动构造/移动赋值）让资源"换主人"而非"复制"。**零法则**：不直接管资源、全用智能指针/容器，则五个特殊成员一个都别写，让编译器生成。

---

## 0. 一句话直觉

> `Matrix a(2,3); Matrix b = a;` 这句"复制"到底复制了什么？竞赛里 `struct` 复制就是**把内存里的字节照抄一遍**。但 `Matrix` 里有指针 `data_` 指向堆上的一大块数据——照抄字节只会抄到**指针的值（地址）**，抄不到**指针指向的数据**。于是 `a` 和 `b` 的 `data_` 指向同一块堆内存。当两个对象都析构时，这块内存被 `delete[]` 两次 → 崩溃。**这就是"浅拷贝"陷阱，也是本篇要解决的核心问题。**

---

## 1. 对象的三种"生死大事"（特殊成员函数）

编译器会为你的类**偷偷生成**几个特殊成员函数，决定对象怎么被创建、复制、销毁：

| 特殊成员 | 语法 | 何时调用 | 编译器默认行为 |
|---|---|---|---|
| 默认构造 | `Matrix()` | `Matrix a;` | 成员逐个默认初始化（内置类型**不清零**） |
| 析构 | `~Matrix()` | 出作用域 / `delete` | 成员逐个析构（**不释放指针指向的内存**） |
| 拷贝构造 | `Matrix(const Matrix&)` | `Matrix b = a;`、传值、返回 | **按位浅拷贝**（照抄指针地址） |
| 拷贝赋值 | `Matrix& operator=(const Matrix&)` | `b = a;`（已存在对象） | **按位浅拷贝** |
| 移动构造 | `Matrix(Matrix&&)` | `Matrix b = std::move(a);` | （C++11，默认存在时）**转移资源，掏空源** |
| 移动赋值 | `Matrix& operator=(Matrix&&)` | `b = std::move(a);` | 同上 |

> 前四个从 C++ 一出生就有，后两个是 C++11 加的"移动"（`08` 详讲）。本篇先吃透拷贝。

## 2. 浅拷贝 vs 深拷贝（核心图示）

**浅拷贝（编译器默认，危险）**：
```
a.data_ ──► ┌─────────── 堆上的 rows×cols 个 float ───────────┐
b.data_ ──► (同一地址)                                         
两个对象共享同一块内存 → 谁先析构，另一个的 data_ 就变成悬空指针 → 二次释放崩溃
```

**深拷贝（我们自己写，安全）**：复制一份**独立的数据**：
```
a.data_ ──► [a 的数据块]
b.data_ ──► [b 的数据块]   ← 与 a 完全独立，各自析构互不影响
```

```cpp
class Matrix {
public:
    Matrix(int r, int c) : rows_(r), cols_(c), data_(new float[r*c]()) {}
    // 拷贝构造：深拷贝
    Matrix(const Matrix& o) : rows_(o.rows_), cols_(o.cols_), data_(new float[o.rows_*o.cols_]) {
        std::copy(o.data_, o.data_ + rows_*cols_, data_);   // 复制数据，不是复制指针
    }
    // 拷贝赋值：深拷贝（注意处理"自赋值"和"旧资源"）
    Matrix& operator=(const Matrix& o) {
        if (this != &o) {                       // 自赋值检查：a = a 不能把自己删了
            delete[] data_;                     // 先释放旧资源
            rows_ = o.rows_; cols_ = o.cols_;
            data_ = new float[rows_*cols_];
            std::copy(o.data_, o.data_ + rows_*cols_, data_);
        }
        return *this;
    }
    ~Matrix() { delete[] data_; }
private:
    int rows_, cols_; float* data_;
};
```

## 3. 三法则 / 五法则 / 零法则（本篇最重要的一句话）

### 3.1 三法则（Rule of Three，C++98）

> **如果一个类需要自定义「析构函数 / 拷贝构造函数 / 拷贝赋值运算符」三者中的任何一个，它几乎必然需要全部三个。**

**为什么？** 因为"需要自定义析构"通常意味着"这个类在管理一份资源"（否则用默认析构就够了）。而管理资源，就**同时**意味着：默认浅拷贝会共享资源（所以要自定义拷贝构造 + 拷贝赋值）。三者是一条命，缺一不可。

**反例（你最容易写的 bug）**：给 `Matrix` 写了析构（释放 `data_`），却忘了写拷贝构造——`Matrix b = a;` 用默认浅拷贝，`a`、`b` 共享 `data_`，双析构崩溃。**本篇 demo 的 TRY-3 就是亲手制造这个崩溃。**

### 3.2 五法则（Rule of Five，C++11）

> C++11 起，再加上「移动构造 / 移动赋值」两个，凑成五个。

**为什么？** 声明了拷贝/析构后，编译器**不会**自动生成移动构造/移动赋值；而一个能深拷贝的类，往往也该能"移动"（把资源从临时对象手里直接抢过来，省一次深拷贝）。移动语义让"值传递大对象"从"复制一整块内存"变成"改一个指针"（`08` 详讲）。

### 3.3 零法则（Rule of Zero，现代首选！）

> **如果你的类不直接管理资源（用 `unique_ptr`/`vector`/`string` 等 RAII 成员来管理），那么五个特殊成员一个都别写，全交给编译器生成。**

```cpp
class Matrix {                 // 零法则：不写任何特殊成员
    std::vector<float> data_;  // vector 自己管理内存、正确深拷贝、正确移动
    int rows_, cols_;
};                             // 拷贝、移动、析构全自动且正确 —— 这就是 07 的智能指针的价值
```

**现代 C++ 的目标：绝大多数类遵循零法则，只有极少数"资源管理类"（如封装 `cudaMalloc` 的类）才需要手写三/五法则。** 你的职责是分清"我在不在直接管资源"。

## 4. 编译器到底什么时候"偷偷"生成什么（速查）

| 你声明了… | 编译器自动生成… |
|---|---|
| 什么都没声明 | 全部六个（默认构造、析构、拷贝、移动都生成） |
| 声明了**任意**构造函数（如带参） | 不再生成默认构造；其余照旧 |
| 声明了析构/拷贝构造/拷贝赋值之一 | **不生成移动**（移动退化为拷贝） |
| 声明了移动构造/移动赋值之一 | **不生成拷贝**（拷贝被删除） |

> 关键推论：**只要写了析构，移动就不再生成了**——所以三法则的类若想享受移动，必须显式补上移动构造/移动赋值（五法则），或用 `= default` 请求回来。

```cpp
class M {
public:
    ~M() { /* 管理资源 */ }
    M(const M&) = default;    // 显式要回拷贝
    M& operator=(const M&) = default;
    M(M&&) = default;         // 显式要回移动
    M& operator=(M&&) = default;
};
```

## 5. 拷贝省略（Copy Elision，预告 08）

有些你以为会拷贝的地方，编译器其实**省略了拷贝**（直接把对象"原地"构造在目的地）：

```cpp
Matrix make() { return Matrix(3, 3); }   // 返回值优化 RVO：不会真的拷贝
Matrix m = make();                        // 也不会拷贝，直接在 m 处构造
```
自 C++17 起，返回值优化（RVO）是**强制**的；但要注意：**就算拷贝被省略了，拷贝构造/移动构造仍然必须"可访问"**（编译期仍会检查）。`08` 会详细展开"移动 + 省略"如何让大对象传值几乎零开销。

## 6. 图示：一个对象的一生

```
Matrix a(2,3);            // ① 构造：分配堆内存
   │
Matrix b = a;             // ② 拷贝构造（深拷贝：独立复制一块堆内存）
   │
Matrix c = std::move(a);  // ③ 移动构造：a 把 data_ 指针"送给" c，a 被掏空（08）
   │
b = c;                    // ④ 拷贝赋值（先删 b 旧资源，再深拷贝 c 的资源）
   │
}                         // ⑤ 出作用域：a(空)、b、c 依次析构，各自释放自己的资源
```

## 7. 易错点

1. **写了析构忘写拷贝 → 二次释放崩溃**（最经典，demo TRY-3）。
2. **拷贝赋值忘了自赋值检查**：`a = a;` 若先 `delete[] data_` 再 `new` 从自己复制 → 读已释放内存，崩溃。用 `if (this != &o)` 挡。
3. **拷贝赋值忘了先删旧资源**：`b = c;` 直接 `data_ = new ...` 而不 `delete[] data_` → `b` 原来的内存泄漏。
4. **`new[]` 配 `delete` 或反之**：未定义行为。
5. **声明了析构却想用移动，却忘了 `= default`**：移动悄悄退化成拷贝，性能白损失（`08` 会教你如何验证）。
6. **误以为默认拷贝是深拷贝**：编译器从不"聪明"地深拷贝你的指针，它只会照抄地址。
