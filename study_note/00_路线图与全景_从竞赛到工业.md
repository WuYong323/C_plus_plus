## 精炼段

你在竞赛里用的 C++ 只是它的**过程式子集**：`struct` 打包数据、STL 容器、裸函数。工业里真正的主角——类、继承、多态、RAII、模板、移动语义、多文件工程——在竞赛中被刻意回避（追求"跑得快、写得快"）。本套笔记按「封装 → 多态 → 现代 C++ → 泛型 → 工程 → 前沿衔接」六模块补齐这一副面孔，每篇都从你已有的经验（`struct`、STL、CUDA 的 `cudaMalloc/cudaFree`、Cool 编译器的 codegen）出发，落到"对象在内存里到底是什么样"。

---

## 1. 一句话直觉

> 你会的 C++，是"**用 C 的方式写 C++**"：数据归数据（`struct`），逻辑归逻辑（裸函数），靠 STL 提供现成容器。工业 C++ 则是"**数据和操作它的函数打包成一个自治的整体**"，并且让编译器在对象出生/死亡时自动帮你管理资源、在调用方法时自动帮你选对版本（多态）。两者是同一门语言，只是后者多了一整套"让大工程不乱"的机制。

---

## 2. 你缺的不是语法，是「第二副面孔」

先诚实地说清楚你现在的处境，这决定整套笔记的靶心：

| 你已经很熟（竞赛 C++） | 你基本没碰（工业 C++） |
|---|---|
| `struct` 打包数据、`pair`/`tuple` | `class`、访问控制（private/public） |
| 裸函数 + 全局数组 | 成员函数、`this`、构造/析构 |
| `new/delete`（还常忘 delete） | RAII、智能指针、所有权 |
| `vector`/`sort`/`lower_bound` | 容器/迭代器/分配器的**设计原理** |
| `sort` 自定义 `cmp` 函数 | 运算符重载、函数对象、lambda 的底层 |
| 单文件提交 | 多文件工程、头文件/链接、CMake |
| `#define` 宏、`inline` 猜测 | 模板、constexpr、编译期计算 |
| 值拷贝（默认行为） | 移动语义、右值引用、零拷贝 |

**关键判断**：你不是"不会 C++"，而是**从过程式到面向对象这条路上，从未系统地走过一遍**。而且——你有别人没有的优势：

1. **你用 C++ 手写 CS143 编译器，而 Cool 本身就是 OOP 语言**。你在 codegen 里生成"动态分发"的分发表，却还没从使用者角度搞懂 C++ 的虚函数。**你已经在编译器内部了，只差回头看一眼使用者视角。**
2. **你做 CUDA/infra**：`cudaMalloc/cudaFree` 必须成对出现——这就是 RAII 要解决的痛点；buffer 的所有权转移——这就是移动语义；编译期选分支——这就是模板。**你早就被这些问题"咬"过，只是没有名字。**

## 3. 为什么「对象模型底层」是你最该吃透的（本套笔记的靶心）

面向对象语法（`class`、`virtual`）只是一层皮。真正决定你写 HPC/infra/编译器时能不能做对的是**皮下面的东西**：

- **虚函数调用到底多贵？** → 一次额外间接跳转（vtable 查表）。这决定你在热点 kernel 里该不该用多态。
- **对象在内存里怎么摆？** → 成员按声明顺序排布 + 对齐填充。这决定你的数据布局是否缓存友好（`06`/`14`）。
- **`this` 是怎么传进成员函数的？** → 作为隐藏的第一个参数（ABI 约定）。这就是你 Cool 编译器 codegen 里 `self` 的传递方式（`17`/`18`）。
- **拷贝 vs 移动 vs 返回值优化** → 决定你的大 buffer 是"真搬"还是"改指针"（`02`/`08`）。

> 一句话：**语法是界面，对象模型是原理。** 你将来读 LLVM/MLIR/TVM 源码、写高性能算子、做深度学习编译器，靠的都是原理这一层。

## 5. 每篇笔记的结构（怎么读，怎么学）

每篇按固定骨架写，方便你建立节奏：

1. **精炼段**（3–5 句）——30 秒抓住本篇核心，也是进 hub 的摘要。
2. **一句话直觉 + 类比**——先建立画面（类比标注"这是简化"）。
3. **为什么需要它**——从你熟的代码/踩过的坑出发，讲设计动机。
4. **技术细节**——准确语法、内存布局、关键参数。
5. **图示**——ASCII 画对象/虚表/内存布局。
6. **可运行 demo**——`projects/learn/cpp/` 下对应工程，`build.bat` 直接跑，改一个参数看效果。
7. **易错点**——竞赛写 C++ 最容易踩的坑。
8. **自测题**——1 概念 + 1 应用 + 1 思考（答案见模块末）。
9. **来源与延伸**——Primer 对应章节、cppreference、工业资料链接。

**学习姿势建议**：先读直觉和类比 → 扫技术细节 → **跑一遍 demo** → 回来精读细节 → 做自测。不要跳过 demo——对象模型这东西，跑一遍、看一遍内存地址，比读十遍文字记得牢。

## 7. 与三条线的衔接（一句话版）

- **编译原理**：Cool 的 `class/inherits/动态分发` 与 C++ 的 `class/继承/虚函数` 是同一套思想的两种语法；`17` 会带你用 C++ 的视角重读你 codegen 里的分发表。
- **系统底层 / HPC / infra**：RAII、移动语义、对象布局、缓存友好——这是写高性能算子、管理 GPU 资源的日常。
- **科研 / PL / 深度学习编译器**：LLVM/MLIR/TVM 用 C++ 实现，对象模型 + 模板 + ABI 是读源码的门票。

## 8. 元层面自测（开工前想清楚这三题）

1. **概念题**：用一句话说出「竞赛 C++」和「工业 C++」的本质区别是什么？（提示：不是语法，是"谁负责管理资源、谁负责选函数版本"）
2. **应用题**：你写 CUDA 时 `cudaMalloc` 后如果某个分支提前 `return` 忘了 `cudaFree`，会怎样？这在 C++ 里应该用什么机制一劳永逸地解决？（提示：你已经在本篇看到答案了——RAII）
3. **思考题**：Cool 语言里 `out_string` 是 `IO` 类的方法，`Main` 继承了 `IO`，所以 `main` 里能直接 `out_string(...)`。这个"子类对象调用父类方法"在 C++ 里对应什么语法？它底层怎么知道该调哪个版本的？（先猜，`04`/`05`/`06` 揭晓）

> 答不上没关系——这正是本套笔记要补的。带着这三题往下读，每篇末尾回来对照。
