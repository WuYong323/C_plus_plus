## 精炼段

继承用「is-a」（是一个）关系表达类型的层次：`Student` 是一个 `Person`，于是复用 `Person` 的数据和接口、再扩展自己的部分。`public` 继承是工业默认（表达 is-a），`protected` 成员是"给子类的后门"（子类可见、外界不可见）。构造时**基类先构造、派生类后构造，析构顺序相反**。两大经典陷阱：**对象切片**（值传递派生类对象到基类参数，只留下基类子对象）和**名字遮蔽**（派生类同名成员盖住基类的）。继承解决了"重复代码"，但它把两个类**耦合**在一起——所以现代 C++ 用「组合优先于继承」来克制它。

---

## 0. 一句话直觉

> 你 Cool 编译器里天天见：`class Main inherits IO`。这句话的意思是 `Main` **是一个** `IO`（is-a），所以 `Main` 自动拥有 `IO` 的方法 `out_string`。C++ 的继承就是同一件事：`class Student : public Person` 说「Student 是一个 Person」，于是 Student 自动继承 Person 的 `name`、`age`、`speak()`，再往上加自己的 `student_id`、`study()`。

## 1. 继承语法与三种继承方式

```cpp
class Base {
public:    int pub_;
protected: int prot_;   // 子类可见，外界不可见
private:   int priv_;   // 只有 Base 自己可见（子类也看不到）
};

class Derived : public Base {   // public 继承（工业默认，几乎总是它）
public:
    void f() {
        pub_;      // OK：public 成员子类可见
        prot_;     // OK：protected 就是"给子类的后门"
        // priv_;  // 错误：private 成员连子类都不可见
    }
};
```

三种继承方式（决定了基类成员在派生类里的**可见性上限**）：

| 继承方式 | 基类 public 成员 → | 基类 protected → | 基类 private → |
|---|---|---|---|
| `public` | public | protected | 不可见 |
| `protected` | protected | protected | 不可见 |
| `private` | private | private | 不可见 |

> **99% 的情况用 `public` 继承**，因为它表达的是「is-a」关系。`private`/`protected` 继承表达的是「has-a / implemented-in-terms-of」（用基类实现自己），几乎总能用「成员组合」替代——**别用**，知道有这回事即可。

**`protected` 存在的唯一意义**：让基类能给子类"开一扇后门"访问某些实现，同时对外界仍然隐藏。它是 `public`（对所有人）和 `private`（只对自己）之间的中间态。

## 2. 构造与析构的顺序（面试高频 + 写代码必须对）

```cpp
class Base {
public:
    Base()  { std::cout << "Base 构造\n"; }
    ~Base() { std::cout << "Base 析构\n"; }
};
class Derived : public Base {
public:
    Derived()  { std::cout << "Derived 构造\n"; }
    ~Derived() { std::cout << "Derived 析构\n"; }
};
// 输出（创建 Derived 对象）：
//   Base 构造        ← 基类先
//   Derived 构造     ← 派生类后
//   ... 使用 ...
//   Derived 析构     ← 派生类先（逆序！）
//   Base 析构        ← 基类后
```

**规则**：构造 = 基类 → 成员 → 自己的构造函数体；析构 = 恰好反过来。

**基类构造函数带参数时，必须在初始化列表里显式调用**：
```cpp
class Person {
public:
    Person(const std::string& name) : name_(name) {}
private:
    std::string name_;
};
class Student : public Person {
public:
    Student(const std::string& name, int id)
        : Person(name),      // 显式调用基类构造，传入 name
          id_(id) {}
private:
    int id_;
};
// 若不写 Person(name)，会尝试调用 Person 的默认构造；Person 没有默认构造 → 编译错误
```

> 这和你 Cool 编译器里生成继承体系时"父类属性先于子类属性初始化"的顺序是一回事（`17` 会对照 codegen）。

## 3. 对象切片（Object Slicing）——继承第一个大坑

**当派生类对象被"按值"赋给/传给基类对象时，派生类多出来的部分被"切掉"，只剩基类子对象。**

```cpp
class Person { public: std::string name; };
class Student : public Person { public: int id; };

void print_person(Person p) {          // 按值传参 → 发生切片！
    std::cout << p.name << "\n";
    // p 里根本没有 id —— 已经被切掉了
}
Student s; s.name = "Alice"; s.id = 2024;
print_person(s);      // 只传了 Person 部分，id 丢失

Person p = s;         // 同样切片：p 只是 s 的 Person 子对象的拷贝
```

**解法**：用**指针或引用**传递，保留动态类型（这就是多态的前提，`05`）：
```cpp
void print_person(const Person& p) { ... }   // 引用：不切片
```
> **为什么切片和虚函数/多态关系重大**：切片掉的不仅是数据，还有"动态类型"。`Person p = s;` 之后 `p` 就真的是个 `Person` 了，调虚函数也不再分发到 `Student` 版本。**多态必须通过指针/引用**，根源就在这。

## 4. 名字遮蔽（Name Hiding）

派生类里声明了与基类同名的成员，会**遮蔽（hide）**基类的所有同名重载（哪怕参数不同）：

```cpp
class Base { public: void f(int); void f(double); };
class Derived : public Base {
public:
    void f(int);              // 只写了这个，却把 Base::f(double) 也藏起来了
};
Derived d;
d.f(3.14);                    // 错误：找不到 f(double)！它被藏了
d.f(3);                       // OK：调 Derived::f(int)
```
**解法**：`using Base::f;` 把基类那组重载"请回来"：
```cpp
class Derived : public Base {
public:
    using Base::f;            // 让 Base 的 f(int)/f(double) 都可见
    void f(int);              // 再覆盖/重载自己想要的
};
```

## 5. 继承 vs 组合（现代 C++ 的重要取舍）

| | 继承（is-a） | 组合（has-a） |
|---|---|---|
| 语义 | `Car` 是一个 `Vehicle` | `Car` 有一个 `Engine` |
| 代码 | `class Car : public Vehicle` | `class Car { Engine engine_; }` |
| 耦合 | 强（子类依赖基类实现细节） | 弱（只依赖接口） |
| 何时用 | 真正的 is-a，且需要多态（`05`） | 复用实现、不确定关系时（**优先**） |

**C++ Core Guidelines C.129 / 经典名言「组合优先于继承」**：继承是 C++ 里**耦合最强**的关系之一，改基类会波及所有子类。能用组合复用的，别用继承。**继承的真正价值在于多态**（`05`）——如果不需要多态，优先组合。

## 7. 易错点

1. **值传递导致切片**：函数参数该用 `const Base&`，却写了 `Base`（按值）。派生类信息丢失、多态失效。
2. **忘了在初始化列表调基类构造**：基类没有默认构造时，派生类构造必须显式 `Base(args)`，否则编译错误。
3. **派生类同名成员遮蔽基类重载**：意外藏掉 `f(double)`。用 `using Base::f;` 救回。
4. **误用 protected/private 继承**：99% 用 public 继承；组合能解决就别继承。
5. **基类析构函数没写 virtual**（`05` 重点）：`Base* p = new Derived; delete p;` 若 `~Base()` 非虚，派生类析构不会执行 → 资源泄漏/未定义行为。**这是继承 + 多态最常见的生产事故。**
