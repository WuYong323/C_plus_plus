## 精炼段

C++20 和 C++23 是一次"现代化补课"：**concepts**（`11` 已讲）让模板约束可读、**ranges** 让算法+视图链式组合、**span** 提供零开销的"非拥有视图"（替代裸指针+长度，系统/HPC 利器）、**std::format/print** 取代啰嗦的 `iostream`、**三路比较 `<=>`** 一行生成全套比较、**coroutines** 原生异步、**modules** 加速编译。C++23 补上 **std::expected**（值或错误，替代异常做预期失败）、**std::mdspan**（多维视图，HPC 矩阵）、**std::flat_map/set**（缓存友好的有序容器）。C++26（已定稿）带来 **reflection**、**contracts**、**std::simd**（[GCC 16.1 已支持](https://isocpp.org/blog/2026/04/gcc-16.1)）。**主线建议：新代码默认 C++20，逐步用 23 特性。**

---

## 0. 一句话直觉

> 老 C++ 写"检查 T 能不能比大小"要写几十行晦涩的 SFINAE；C++20 一句 `template<Comparable T>` 就懂。老 C++ 传"数组"要同时传指针和长度（还常写错）；C++20 的 `span` 一个对象搞定。**C++20/23 不是加"更多玩具"，而是把过去"能做但难做、易错"的事，变成"简洁且编译器帮你看住"。**

## 1. Concepts（C++20）——11 已详讲，这里一句话

```cpp
template<std::integral T>   // 用标准库 concept 约束
T add(T a, T b) { return a + b; }
```
把"类型必须满足什么"写成具名约束，错误信息从几百行变一句人话。

## 2. Ranges（C++20）：算法与视图的组合

老写法传"两个迭代器"，`ranges` 直接传**整个范围**，还能用 `|` 串联**视图（view）**做惰性流水线：

```cpp
#include <ranges>
#include <algorithm>
#include <vector>

std::vector<int> v{5,1,4,2,3};

// 老写法
std::sort(v.begin(), v.end());

// C++20 ranges：传整个容器
std::ranges::sort(v);

// 视图流水线：过滤 → 变换 → 取前 3，全部惰性（不产生中间容器）
auto even_squares = v
    | std::views::filter([](int x){ return x % 2 == 0; })   // 只留偶数
    | std::views::transform([](int x){ return x * x; });    // 平方
for (int x : even_squares | std::views::take(3))            // 取前 3
    std::print("{} ", x);
```
> **价值**：视图是**惰性**的（遍历时才算，不生成中间 vector），且可无限组合。你 infra 里"过滤+映射+归约"的流水线，用 ranges 表达清晰且零额外分配。

## 3. std::span（C++20）：非拥有的连续视图（系统/HPC 利器）

`span<T>` = "指向一段连续 T 的指针 + 长度"，**不拥有**数据，零拷贝、零分配：

```cpp
#include <span>
#include <vector>

void process(std::span<const float> data) {   // 替代 (const float*, size_t)
    for (float x : data) { /* ... */ }
    std::print("len={}\n", data.size());       // 自带长度，不会传错
}

std::vector<float> v(1000);
process(v);            // vector 自动转 span（隐式转换）
float arr[5] = {1,2,3,4,5};
process(arr);          // 裸数组也能转 span
```

**为什么取代裸指针 + 长度**：① 长度和数据绑在一起，杜绝"指针和长度传错"这类经典 bug；② 支持范围 for、`.size()`、`.subspan()` 切片；③ 零开销（就是个 struct 两个字段）。**这是你写 CUDA kernel 包装、算子接口时最该用的类型**——比 `const float*` + 手传 `n` 安全得多。

## 4. std::format / std::print（C++20/23）：现代格式化

```cpp
#include <format>     // C++20
#include <print>      // C++23（直接打印）

std::string s = std::format("value={} hex={:#x} pi={:.2f}", 42, 255, 3.14159);
// value=42 hex=0xff pi=3.14

std::print("hello {} {:.3f}\n", "world", 2.71828);   // C++23：不再写 cout << 链
```
- 类型安全（不用 `printf` 的 `%d` 传错类型）、可读、性能好。
- `{}` 自动按类型格式化，`{:.2f}` 控制精度，`{:x}` 十六进制。

## 5. 三路比较 `<=>`（C++20）：一行生成全套比较

```cpp
#include <compare>

struct Point {
    int x, y;
    auto operator<=>(const Point&) const = default;   // 生成 == != < <= > >= 全套
};
Point{1,2} < Point{2,3};   // true，自动按 x 再 y 字典序比较
```
> 省掉手写六个比较运算符（`03` 里你要一个个写），且默认实现按成员声明顺序逐字段比较。

## 6. Coroutines（C++20）：原生异步

`co_await`/`co_yield`/`co_return` 让函数可以"暂停-恢复"，是异步/生成器/流式处理的基石：

```cpp
#include <generator>    // C++23 标准生成器
std::generator<int> fib() {       // 惰性生成斐波那契
    int a = 0, b = 1;
    while (true) { co_yield a; int t = a + b; a = b; b = t; }
}
for (int x : fib() | std::views::take(10)) std::print("{} ", x);
```
> **对你（infra）的意义**：异步 IO、流式数据、生成器。但注意：coroutines 涉及堆分配和状态机，性能敏感场景要了解其代价（可能动态分配协程帧）。编译器和 `generator` 已相当成熟，但深度优化仍需谨慎。

---

## 7. Modules（C++20）：加速编译

`#include` 是"文本复制"，每个 `.cpp` 都要重新解析头文件（慢）。`module` 是"预编译的接口"：

```cpp
// math.ixx（模块接口）
export module math;
export int add(int a, int b) { return a + b; }

// main.cpp
import math;          // 代替 #include，直接导入预编译模块
int x = add(1, 2);
```
- **收益**：编译大幅加速（头文件不再被每个 TU 重复解析）、隔离宏污染。
- **现状**：三大编译器（GCC 15、Clang 17+、MSVC）都已较好支持；但生态迁移仍在进行（很多库还没模块化），**新项目可逐步尝试**。你的 g++ 15.2 支持 `-fmodules-ts`（GCC 的模块实现）。

## 8. C++23 关键新增

| 特性 | 用途 |
|---|---|
| **`std::expected<T,E>`** | "值或错误"（09 已讲），替代异常处理预期失败 |
| **`std::mdspan`** | 多维非拥有视图（HPC 矩阵的"标准答案"） |
| **`std::flat_map/set`** | 有序 + 缓存友好（连续内存的 map/set） |
| **`std::print`** | 现代打印（§4） |
| **`std::generator`** | 标准生成器（§6） |
| **monadic optional** | `optional.and_then/or_else/transform` 链式处理"可能为空" |
| **deducing this** | 显式对象参数，简化重复的 const/非 const 重载 |

## 9. C++26 前瞻（已定稿，编译器陆续支持）

| 特性 | 意义 |
|---|---|
| **Reflection（反射）** | 编译期检查/生成代码（枚举成员、结构字段），终结大量宏和手写序列化 |
| **Contracts（契约）** | 前置/后置/不变量条件，替代大量 `assert`，可静态检查 |
| **`std::simd`** | 显式 SIMD 向量类型，写"一条指令算 N 个"（HPC 友好） |
| **safety hardening** | 边界/生命周期检查（`15` 的 profiles 落地） |

> 参考：[GCC 16.1 发布（C++26 reflection/contracts/safety hardening，C++20 成默认标准）](https://isocpp.org/blog/2026/04/gcc-16.1)、[CppCon 2026 主题演讲《How C++26 Changes the Way We Write Code》(Timur Doumler)](https://isocpp.org/blog/2026/08/cppcon-2026-keynote-how-cpp26-changes-the-way-we-write-code-timur-doumler)。**你的 g++ 15.2 已实测支持 `-std=c++23` 和实验性 `-std=c++26`**（现在就能试 `std::expected`/`std::print`/`std::mdspan`）；升级到 GCC 16 后 C++20 将是默认标准。

## 10. 易错点

1. **项目还在 C++17 却写 concepts/ranges**：编译不过。**先确定 `-std` 版本**再选特性。
2. **`span` 悬空**：`span` 不拥有数据，若它指向的对象被销毁，`span` 变悬空（和裸指针同样的生命周期问题，但至少长度还在）。
3. **ranges 视图是惰性的**：`auto v = vec | views::filter(...)` 只是"描述"，遍历时才计算；若 `vec` 已销毁，视图悬空。
4. **`<=>` 默认生成**：默认按声明顺序逐字段比，字段顺序变了，比较语义也变。
5. **coroutines 的隐藏分配**：协程帧可能堆分配，性能敏感处要了解编译器是否做了优化。
6. **modules 与 #include 混用**：迁移期混用需小心宏/ODR 边界。

## 11. 自测题

1. **概念题**：`span<T>` 和 `vector<T>` 的本质区别是什么？为什么"非拥有视图"在系统/HPC 里比"裸指针+长度"更安全？
2. **应用题**：用 `std::ranges` + `views::filter/transform` 把一个 `vector<int>` 里的偶数平方后排序输出，并说明这个流水线为什么不产生中间容器。
3. **思考题**：`std::expected<T,E>` 和异常在"错误处理"上各适合什么场景？为什么 C++ 同时保留两者（而不是统一成一种）？
